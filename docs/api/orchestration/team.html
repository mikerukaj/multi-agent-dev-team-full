orchestration.team

The PM -> Coder <-> QA team: one LangGraph graph over the shared TeamState.

The PM writes the spec and tasks, publishes one task at a time on the handoff key, and the Coder builds each task in one shared workspace and reports back (specs/001-autonomous-dev-team/contracts/handoff-protocol.md). Every exchange between the Coder and QA then travels as an A2A message through the asyncio broker: the graph sends each one on behalf of the agent whose turn it is, and never calls QA directly (specs/002-qa-feedback-loop-mcp/contracts/).

Before each QA review the Coder reflects on its program; after a fix_needed verdict QA sends its fix instruction list to the Coder, and the loop repeats until QA says complete or the iteration limit is reached.

Production hardening (003) makes every run end cleanly and resumable: each stage saves a checkpoint, the run holds a lock and always writes a final record, SIGINT/SIGTERM stop it at the next call boundary, and --resume RUN_ID continues it from its last completed stage (specs/003-production-hardening/contracts/cli.md).

Usage:

python -m orchestration.team "" [--max-iterations N] [--max-steps N] [--timeout SECONDS] python -m orchestration.team --resume RUN_ID

def build_team_graph( pm: agents.pm_agent.PMAgent, coder, clients: dict[str, messaging.broker.A2AClient], services: orchestration.services.RunServices | None = None, on_stage: Optional[Callable[[str, str, str, dict], NoneType]] = None) -> Any:

Compile the team graph.

pm -> (consolidate) -> dispatch <-> coder -> reflect -> qa -> (fix -> reflect -> qa)* -> finish. clients are the A2A clients from team_clients: every Coder <-> QA exchange goes through them; only the Coder's own work (build, reflect) is direct. A resumed run starts at state["resume_from"] instead of pm. With services, a stop request ends the run interrupted at the next node; on_stage is called after each completed stage (checkpoints, stage events).

def run_team( requirement: str, pm: agents.pm_agent.PMAgent | None = None, coder=None, workspace_root: pathlib.Path = PosixPath('workspace'), on_update: Optional[Callable[[str, dict], NoneType]] = None, *, qa=None, max_iterations: int = 5, a2a_timeout_seconds: float = 1800.0, services: orchestration.services.RunServices | None = None) -> orchestration.state.TeamState:

Run the PM -> Coder <-> QA team on requirement and return the final state.

coder is any object with run(task, workspace) -> CoderResult; qa is any object with run_iteration(context) and final_report(request). QA is reached only through the A2A broker this function opens and closes. on_update(node, update) is called after every node. services holds the run's shared helpers (a fresh RunServices by default); its run_id names the run, and every agent that has attach is given it.

The run holds its lock throughout, saves a checkpoint after each stage, and writes its final record (.runs/<run_id>/run.json) however it ends (FR-212, FR-213).

Raises:
  • ValueError: if requirement is empty or max_iterations is outside 1-10.
  • SandboxUnavailableError: if no coder/qa is given and Docker is unavailable.
def resume_team( run_id: str, pm: agents.pm_agent.PMAgent | None = None, coder=None, workspace_root: pathlib.Path = PosixPath('workspace'), on_update: Optional[Callable[[str, dict], NoneType]] = None, *, qa=None, budget_usd: float | None = None, settings_overrides: dict | None = None, services: orchestration.services.RunServices | None = None, a2a_timeout_seconds: float = 1800.0) -> orchestration.state.TeamState:

Continue run run_id from the stage after its last checkpoint (FR-213a-d).

The workspace is restored to the checkpoint, a ResumeAttempt is recorded, and the run goes on with the same run ID, iteration count, usage, cost and A2A log.

Raises:
  • ResumeRefused: naming the reason, without changing any file, if the run is still going, ended for good, has an unusable checkpoint, asks for other settings, or ended budget_exceeded without a higher budget_usd.
