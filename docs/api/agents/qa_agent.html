agents.qa_agent

QA & Debugger Agent: writes and runs real pytest tests, reviews the code, reports findings.

One QA iteration is a fixed pipeline, not an open-ended agent loop (research R8): write tests from the spec and the program's public interface only, run them in the network-less sandbox, repair a suite that does not load, then review the full code with the results and return a normalised findings list (the fix instruction list) and a verdict worked out in code. Every file read and write goes through the MCP file-tool server. The team reaches this agent only through its A2A endpoint, and this module never imports the Coder (SC-110). See specs/002-qa-feedback-loop-mcp/.

Tries per structured QA reply: the first answer, plus one corrected answer after a rejection. A single paraphrased criterion or cut-off reply used to end the whole iteration (baseline benchmark 2026-10-20: 6 of 10 runs).

class QAStepError(builtins.Exception):

One step of a QA iteration could not finish; the message says why.

failure is set when the step failed because a dependency (the model service, MCP or the sandbox) could not be used (FR-209c).

Summarise the run and write .qa/report.md through MCP (no model call).

The session is not guarded: the report is the run's last, quick write, and it must be written even when the run is stopping (the guard refuses calls then).
